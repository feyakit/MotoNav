# Square UI review — work in progress

The original reference was the user's uploaded mockup. The previous session saved reference crops for the battery summary and cell page in `summary-compare.png` and `cells-compare.png`. The original temporary upload was no longer present after the environment restarted, so reference crops for navigation, music, BLE and menu cannot currently be regenerated. The two comparison files reuse the previously saved left-hand crops; the current renders are on the right.

`summary.png`, `cells-1.png` through `cells-4.png`, `menu.png` and `bluetooth.png` are 480×480 software renders generated by compiling the same `BmsSquareUI.h` and `SquarePages.h` drawing functions used by the firmware. The host Canvas approximates Arduino_GFX shape rasterization; none is an ESP32 framebuffer capture or proof of physical appearance. Bluetooth preview peer names, addresses, RSSI and phone state are simulated exclusively in the host renderer. The device page uses only discovered advertisements.

Differences from the mockup remain substantial: The static battery and menu labels now use a small anti-aliased Chinese glyph subset, and the SOC uses a bold numeric subset. Other text still uses a pixelated bitmap font; dynamic metadata, actual album art, reference icons/gradients and high-fidelity map layout are not finished. The menu is two columns by three rows as requested, while the pictured promotional image uses three columns by two rows. Health and BMS status are `--` unless valid data exists. The simulation fixture displays 18.84 Ah explicitly as a simulated field; the unknown real protocol never supplies it. No screen has completed three verified visual iterations and navigation/music do not yet have an accurate end-to-end screenshot.

Navigation: tap MENU at the top left for the menu or SOC at the top right for the battery screen. Existing swipe paths remain. Battery: tap the dashboard for cells; swipe vertically for groups of six, tap the upper left to return or upper right to toggle bars/list. Bluetooth: tap SCAN, tap a discovered row to connect, swipe for remaining entries, or tap DISCONNECT to stop retries. BLE subscriptions remain explicitly selected via serial diagnostics; the touchscreen does not guess characteristics.

Host render examples:

```sh
g++ -std=c++17 -O2 firmware/tests/render_bms_square.cpp -o /tmp/render_bms_square
/tmp/render_bms_square summary /tmp/summary.ppm
/tmp/render_bms_square cells0 /tmp/cells.ppm
/tmp/render_bms_square menu /tmp/menu.ppm
/tmp/render_bms_square bluetooth /tmp/bluetooth.ppm
```

The simulation firmware requires `--build-property 'compiler.cpp.extra_flags=-DMOTONAV_BMS_SIMULATION=1'`. No image is used as a firmware background. No real screen, touch, navigation, music or BLE interaction has been verified for these changes.

The Chinese and numeric glyphs are rasterized from Noto Sans CJK SC; generation source and the full copyright/license notice are in `firmware/tools/generate_square_glyphs.py` and `firmware/licenses/Noto-CJK-copyright.txt`. The user sent the mockup again in the current chat, but no local original file path was exposed to this execution environment. Existing saved battery crops are reused; four other reference comparisons still need the original file.

Battery comparison history: `history/*-01.png` is the first saved square battery rendering (`67feb66`); `history/*-02.png` adds the simulated capacity and cell high/low highlighting (`98fc942`); the current `*-compare.png` adds Chinese static labels and smoother numbers. These are three saved snapshots across two successive revisions, not proof that every page completed three rounds of visual correction. All right-hand images are host simulations, not hardware framebuffer captures.

The anti-aliased glyphs draw into the existing framebuffer; they are not image backgrounds. The host renderer uses the same draw routines, but performance on ESP32—especially the navigation MENU label drawn during map updates—has not been measured. Frame rate, touch latency and runtime memory must be checked on hardware before use as a navigation display.
