# 2.16 visual review — work in progress

Reference: the user's promotional mockup. The reference crops are enlarged low-resolution JPEG regions, not source design files. The implementation currently covers the two battery screens only. Navigation, music, BLE device list, and menu have not been redesigned or compared to the reference.

The 480×480 `summary.png` and `cells-*.png` are generated by compiling and executing `BmsSquareUI.h`, the same drawing functions used by the firmware. The host `Canvas` approximates Arduino_GFX shape rasterization and uses the repository bitmap font. These images are software renders, **not device framebuffer captures**, and do not prove exact pixel agreement with the board. The side-by-side images combine these renders and crops of the reference. No actual device or capture was available.

Differences: the existing bitmap font is pixelated and English-only, unlike the smooth Chinese typography in the reference; the status bar deliberately says SIMULATED/SIM DATA rather than inventing a time or phone status. The capacity is an estimate of 45 Ah × SOC and marked EST. CAPACITY; health and a normal/safe BMS status are not asserted because they are not available. The six rows in the reference are four selectable groups of six on the device. Green gauge and bars are flat, without the reference's glow and gradient. The maximum/minimum indicators use the simulation fixture and do not imply actual pack values.

On the existing weather page swipe left to the BMS page. Tap the dashboard to show cells 1–6; tap the body to cycle through the four groups, and tap the top area to return to the dashboard. Swipe right to weather. Touch, screen geometry, navigation/media coexistence and actual appearance still need testing on the device. The existing adaptation contains circular clipping in slide animation and non-cardinal rotation, which has not yet been reworked for the requested square appearance; the preview is not a validation of those paths.

Reproduce raw renders from the repository root:

```sh
g++ -std=c++17 -O2 firmware/tests/render_bms_square.cpp -o /tmp/render_bms_square
/tmp/render_bms_square summary /tmp/summary.ppm
/tmp/render_bms_square cells0 /tmp/cells-1.ppm
/tmp/render_bms_square cells1 /tmp/cells-2.ppm
/tmp/render_bms_square cells2 /tmp/cells-3.ppm
/tmp/render_bms_square cells3 /tmp/cells-4.ppm
```

Default firmware retains unknown-protocol/no-data behavior. The explicit `MOTONAV_BMS_SIMULATION=1` build flag is required for the simulated numbers shown in these renders. No image is used as a firmware background.

Verification on this change: the 2.16 default build with ESP32 Arduino core 3.3.10 succeeded (1,284,167 bytes of application; 89,076 bytes static RAM). Host tests include the unavailable/stale state and all four 24-cell groups, plus the existing media, rotation, idle-timer and flasher tests. No physical screen, touch, phone/BMS radio, visual or battery test has been run.

The separately compiled `MOTONAV_BMS_SIMULATION=1` build also succeeded (1,284,243 bytes of application; 89,076 bytes static RAM).
